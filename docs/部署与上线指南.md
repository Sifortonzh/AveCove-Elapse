# AveCove Elapse 部署与上线指南

更新时间：2026-07-21
适用系统：Ubuntu 22.04 / 24.04

## 1. 公网结构

```text
手机 / 电脑
    │ HTTPS
    ▼
  Nginx / Caddy ── 反向代理与 HTTPS
    │
    ▼
AveCove Elapse 应用
    │
    ├── PostgreSQL：匿名同步身份、学习记录、评论、审核、AI 用量
    ├── SMTP：邮箱验证码（可选）
    └── AI 厂商 API：知微解析与追问（可选）
```

新版 `.docx` 与 PDF 题库文件在浏览器内解析；旧版 `.doc` 会临时发送到本应用，在服务器内存中提取文字，原文件不落盘。多端同步只保存进度、收藏、笔记、设置与昵称；另一台设备仍需自行导入对应题库。

## 2. 服务器准备

- 2 核 CPU、4 GB 内存、20 GB 以上磁盘
- 安装 Docker Engine 与 Docker Compose v2
- 域名 A/AAAA 记录指向服务器
- 防火墙仅开放 22、80、443；PostgreSQL 不开放公网端口
- SSH 使用密钥登录，关闭密码登录

建议部署目录：`/opt/avecove-elapse`。当前 Docker Compose 默认只启动 PostgreSQL 与应用，应用绑定到服务器本机 `127.0.0.1:3011`，适合已有 Nginx、宝塔或其他反向代理的服务器。Caddy 仅在需要时通过 `docker compose --profile caddy up -d` 启用。

## 3. 第一次部署

将项目上传到服务器后：

```bash
cd /opt/avecove-elapse
cp .env.example .env
```

生成四份彼此独立的随机密钥：

```bash
openssl rand -base64 36
openssl rand -base64 36
openssl rand -base64 36
openssl rand -base64 36
```

分别写入 `.env` 的 `POSTGRES_PASSWORD`、`SYNC_SECRET`、`CONFIG_ENCRYPTION_KEY`、`ADMIN_KEY`。同时设置真实 `DOMAIN`，并把 `NEXT_PUBLIC_SITE_URL` 改为完整的 `https://你的域名`。这些值不能提交到 GitHub，也不要发送到群聊。

如需邮箱验证码，只在服务器的 `.env` 中填写 SMTP 相关字段，不要把账号或密码提交到 GitHub，也不需要在网页中配置：

```dotenv
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=你的QQ邮箱或Foxmail邮箱
SMTP_PASS=QQ邮箱生成的SMTP授权码
SMTP_FROM=红豆生南国 <你的QQ邮箱或Foxmail邮箱>
```

QQ 邮箱和 Foxmail 邮箱使用 `smtp.qq.com`。使用 465 端口时设置 `SMTP_SECURE=true`，密码必须使用邮箱设置中生成的 SMTP 授权码。修改后需重新创建应用容器，再从登录界面发送一次验证码并检查收件箱及垃圾邮件目录。

普通用户可以在服务启动后从首页左下角进入“自定义AI”（`/custom-ai`），保存自己的 Key，不需要管理员权限。站点公共 AI 从 `/admin/ai` 配置；`.env` 中的 `OPENAI_API_KEY` 只作为可选兜底。然后启动：

```bash
docker compose up -d --build
docker compose ps
```

如果服务器已有 Nginx，请将域名反向代理到 `http://127.0.0.1:3011`，不要停止其他网站，也不要把 PostgreSQL 或应用端口直接开放到公网。为兼容旧版 `.doc` 导入，请在该站点的 Nginx 配置中设置 `client_max_body_size 25m;`。AI 处理非标准长题库时可能需要数分钟，建议为 AI 导入接口单独延长等待时间，避免 Nginx 返回 HTML 格式的 504 页面：

```nginx
location = /api/import-ai {
    proxy_pass http://127.0.0.1:3011;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    proxy_read_timeout 600s;
    proxy_send_timeout 600s;
    proxy_buffering off;
}
```

标准 306 文件若已同时包含完整题干、选项和明确答案，会优先在浏览器本地确定性整理，不再等待 AI。修改 Nginx 后应先检查配置，再平滑重载服务。

访问 `https://你的域名/api/health`，看到 `status: ok` 后，再访问首页。

## 4. 学号与邮箱规则

- 学号是多端同步的主键，但原始学号不进入数据库。
- 服务器使用 `SYNC_SECRET` 将学号转换为不可逆标识；不同服务器密钥会产生不同标识。
- 不绑定邮箱也可以使用学号同步。
- 绑定邮箱时必须通过验证码；之后可用“邮箱＋验证码”登录。
- 评论区公开显示昵称，不公开学号和邮箱。
- 用户可在同步面板退出、导出记录或注销账号。注销会级联删除云端学习记录、评论、点赞和举报。

学号不是高安全级别的密码。请不要用本系统保存患者信息、临床隐私或其他高敏感内容。

## 5. 评论审核

- 普通评论自动公开；命中敏感词时进入待审核队列。
- 同一评论收到 3 次举报后自动转入待审核。
- 用户可以删除自己的评论。
- 管理员访问 `/admin`，输入 `.env` 中的 `ADMIN_KEY`，可通过、隐藏评论或禁言 7 天。
- 管理操作会写入 `moderation_actions` 表。

## 6. AI 费用控制

- `AI_DAILY_LIMIT` 控制每个同步身份或匿名访客每日请求次数，默认 20 次。
- 普通用户从首页左下角进入“自定义AI”（`/custom-ai`），无需管理员权限即可选择预置厂商并使用自己的 Key；配置只保存在当前浏览器。
- 管理员访问 `/admin/ai`，使用 `.env` 中的 `ADMIN_KEY` 配置全站公共 AI 或自定义 OpenAI 兼容接口。
- 厂商预设的接口地址和模型名称都可以修改；正式使用前应以厂商控制台当前说明为准。
- 后台保存的 AI 密钥采用 AES-256-GCM 加密后写入 `app_settings`，密钥明文不会回传浏览器。`CONFIG_ENCRYPTION_KEY` 丢失后将无法解密，必须重新填写 API Key。
- 建议同时在 API 服务商后台设置月度预算和费用告警。
- 如暂不使用 AI，不配置后台且将 `OPENAI_API_KEY` 留空即可，其他功能仍可运行。

## 7. 备份、恢复与日志

手动备份：

```bash
./scripts/backup.sh
```

备份默认保存到 `backups/`，保留 14 天。配置 `BACKUP_REMOTE` 并安装 rclone 后，可复制到异地存储。

恢复前请先停止外部访问，并使用绝对路径：

```bash
./scripts/restore.sh /opt/avecove-elapse/backups/avecove-elapse-日期.sql.gz
```

安装 Ubuntu 自动安全更新、每日备份和备份日志轮转：

```bash
sudo ./scripts/install-server-maintenance.sh /opt/avecove-elapse
```

Docker 日志已限制为每个容器最多 5 个、每个 10 MB。

## 8. GitHub 自动部署

将此目录上传到 GitHub 后，在仓库 Settings → Secrets and variables → Actions 中添加：

- `DEPLOY_SSH_KEY`：仅用于部署的 SSH 私钥
- `SERVER_HOST`：服务器 IP 或域名
- `SERVER_USER`：部署用户
- `SERVER_PATH`：`/opt/avecove-elapse`

推送到 `main` 会执行检查，并通过 `.github/workflows/deploy.yml` 更新服务器。服务器上的 `.env` 和 `backups/` 不会被覆盖。

## 9. 更新与回滚

更新前先执行备份。手动更新：

```bash
docker compose up -d --build --remove-orphans
docker compose ps
```

回滚时切回上一个 Git 标签或提交，再重新构建。数据库结构变更前必须先备份。

## 10. 上线后监测

- 每周检查 `/api/health`、容器状态和磁盘空间。
- 每月抽查一次备份可恢复性，而不是只看备份文件是否存在。
- 定期查看评论审核队列和 AI 请求量。
- 安全或版权投诉应先隐藏相关内容，再核实处理。
